# 对比不同模型的输出质量、响应速度和成本

模型对比不是“问一句然后凭感觉选模型”，而是一个小型基准测试（benchmark）：

1. 固定题目、提示词和参数。
2. 分别记录质量、速度、用量和价格。
3. 根据业务场景决定权重，而不是追求一个万能冠军。

## 一、三个指标分别怎么测

### 1. 输出质量

质量必须先定义标准。建议每类能力准备 3～10 道题，并使用 0～10 分 rubric：

| 题型 | 评分重点 |
| --- | --- |
| 推理 | 结论正确、过程完整、没有算术错误 |
| 事实问答 | 事实准确、范围符合题目、不过度编造 |
| 结构化输出 | JSON 可解析、字段正确、格式完全遵守 |

同一道题让每个模型运行 3 次，隐藏模型名称后盲评，最后取平均分。这样可以区分：

- **正确率**：答对了多少。
- **一致性**：同一题多次回答是否稳定。
- **格式合规率**：能否被下游程序直接解析。

不要只看“语言听起来漂亮”。生产系统里，结构化输出解析失败一次，可能比少快 200 ms 更昂贵。

### 2. 响应速度

流式场景至少记录两个时间：

- **TTFT（Time To First Token）**：请求发出到第一个内容 token 到达的时间，决定用户感知的等待时间。
- **总耗时**：请求发出到完整回答结束的时间，决定一次任务多久完成。

还可以计算输出速度：

$$
\text{输出速度} = \frac{\text{输出 token 数}}{\text{总耗时} - \text{TTFT}}
$$

比较速度时必须固定输入、输出长度和网络环境。一次结果不可靠，至少重复 3 次并查看中位数；平均值容易被偶发网络抖动拉高。

### 3. 成本

成本应使用 API 返回的真实 token 用量，而不是用字符数猜测：

$$
\text{成本} = \frac{\text{输入 token} \times \text{输入单价} + \text{输出 token} \times \text{输出单价}}{1{,}000{,}000}
$$

单价通常按“每百万 token”公布。流式请求要确认最后一个 chunk 是否携带 usage；本实验通过 `stream_options.include_usage` 请求它。免费模型也建议记录成本为 0，而不是忽略成本字段，便于以后替换模型。

## 二、运行本项目的实验

先查看固定题目和评分标准，不会发起网络请求：

```powershell
\.venv\Scripts\python.exe src\ai_learning\model_compare.py
```

设置模型列表时，`MODEL_COMPARE_MODELS` 是 JSON 数组。`input_price` 和 `output_price` 的单位是“美元 / 百万 token”：

```powershell
$env:MODEL_COMPARE_MODELS = '[{"name":"glm","base_url":"https://open.bigmodel.cn/api/paas/v4/","api_key_env":"ZHIPU_API_KEY","model":"glm-5.3-flash","input_price":0,"output_price":0},{"name":"qwen","base_url":"https://api.siliconflow.cn/v1","api_key_env":"SILICONFLOW_API_KEY","model":"Qwen/Qwen2.5-7B-Instruct","input_price":0,"output_price":0}]'
\.venv\Scripts\python.exe src\ai_learning\model_compare.py --live
```

输出是一行一个 JSON 结果，包含 `ttft_seconds`、`total_seconds`、`output_tokens_per_second`、`usage` 和 `estimated_cost_usd`。把每个模型每道题运行 3 次，再对结果按题型汇总。

## 三、如何做选择

不要直接问“哪个模型最好”，而要问“哪个模型对这个场景的单位价值最高”：

| 场景 | 优先级 |
| --- | --- |
| 客服首屏回复 | 质量达标后优先 TTFT 和稳定性 |
| 批量摘要 | 总成本、总耗时、长文本质量 |
| 代码/结构化抽取 | 正确率、格式合规率、一致性 |
| 高峰期服务 | 限流、错误率、备用模型可用性 |

一个实用的淘汰顺序是：先淘汰质量不达标的模型，再在剩余模型中比较 P50/P95 延迟和每次请求成本。不要把不同题目、不同 token 上限、不同温度下的结果放在同一张排行榜里。

# 指数退避重试实现

## 学习笔记

### 1. 作用

这个函数的作用是：当某个调用失败时，不是立刻报错，而是等待一段时间后重试。这样可以避免短时间内大量重复请求打到服务端。

核心思想：

- 失败后重试
- 重试间隔越来越长
- 加入随机抖动，避免同时重试

---

### 2. 关键点

```python
import time
import random
```

- `time`：用于等待
- `random`：用于增加随机延迟

```python
def retry_with_backoff(func,max_retries=3,base_delay=1.0,max_delay=60):
```

- `func`：要执行的函数
- `max_retries`：最多重试几次
- `base_delay`：基础等待时间
- `max_delay`：最长等待时间

```python
retryable_status={429,500,502,503,504}
```

这些是常见的“可重试”HTTP 状态码，只有这些错误才会重试。

---

### 3. 重试逻辑

```python
for attempt in range(max_retries+1):
    try:
        return func()
    except Exception as e:
        status_code = getattr(e, 'status_code', None)
```

意思是：

- 先尝试调用函数
- 如果成功就直接返回
- 如果失败，检查异常中的状态码

```python
if status_code not in retryable_status:
    raise
```

只有允许重试的错误才继续，否则直接抛出。

```python
if attempt == max_retries:
    raise
```

如果已经到了最后一次机会，也直接抛出异常，不再继续重试。

---

### 4. 指数退避

```python
delay = min(base_delay * (2**attempt), max_delay)
```

这表示等待时间按指数增长：

- 第 1 次：1s
- 第 2 次：2s
- 第 3 次：4s
- 第 4 次：8s

也就是：重试越多，等待越久。

```python
jitter = random.uniform(0, delay * 0.5)
time.sleep(delay + jitter)
```

这里加入随机抖动：

- 让每次重试的等待时间不完全一致
- 防止大量请求在同一时刻同时重试

这就是避免“惊群效应”。

---

### 5. 惊群效应

惊群效应就是：很多请求同时失败，然后一齐重试，造成系统瞬间压力暴增。

而随机抖动的作用就是：

- 打散重试时间
- 降低集中冲击
- 让系统更稳定

---

### 6. 一句话总结

这段代码的本质是：对失败请求使用“指数退避 + 随机抖动”的重试策略，减少瞬时冲击，提高系统稳定性。

---

### 7. 流程说明

```mermaid
flowchart TD
    A[调用 func()] --> B{调用成功?}
    B -- 是 --> C[返回结果]
    B -- 否 --> D[捕获异常]
    D --> E{status_code 是否可重试?}
    E -- 否 --> F[直接抛出异常]
    E -- 是 --> G{是否到达最大重试次数?}
    G -- 是 --> F
    G -- 否 --> H[计算 delay = min(base_delay * 2^attempt, max_delay)]
    H --> I[加入随机抖动]
    I --> J[sleep(delay + jitter)]
    J --> A
```

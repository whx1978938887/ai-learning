# Day 14：检索与分块效果对照

**今天的目标：**做一组可重复的小实验，比较分块或检索参数，而不是凭一条好答案或直觉调优。

## 1. Gold set：先准备参考答案

Gold set（标注集/标准集）是用于比较系统的固定问题集合。每个问题提前标注：

- 预期答案要点；
- 哪些来源文档/片段能支持答案；
- 资料里是否根本没有答案。

例如：

| 问题 | 相关来源 | 可回答？ |
|---|---|---|
| 退货要在几天内申请？ | `return.md` | 是 |
| 订单在哪里查询？ | `account.md` | 是 |
| 周日办公室开门吗？ | 无 | 否 |

标注集不用很大才有价值；5 条可用于学习，但不足以代表所有真实用户问题。它的重点是：每次比较都使用同一批问题和标注。

## 2. Recall@k：正确来源有没有被找到

Recall@k（前 k 个结果召回率）问的是：相关来源是否出现在排名前 k 的候选里。定义要写清楚：

```text
Recall@k = 被找回的相关来源数 ÷ 标注的相关来源总数
```

单个问题若有 2 个相关来源、检索 Top-3 找到 1 个，则该问题的 Recall@3 为 `1/2 = 0.5`。对多个问题，可以把相关来源总数累加计算整体值，也可以先逐题计算再取平均；两种算法含义略不同，报告时说明采用哪一种。

它评估的是**检索**，不是答案整体正确。其他有用检查包括：

- 候选是否太多无关内容（噪声）？
- 第一条相关结果排得是否靠前？
- 回答是否有证据支持、引用是否正确？

## 3. 控制实验：一次改一个因素

比较 chunk size、overlap、Top-k 等参数时，固定其他条件和问题集。一次只改变一个参数，才能大致知道差异从哪里来。例如先比较两种 chunk size，保持 embedding 模型、查询和 Top-k 不变。观察到提升后再测另一个因素。

记录表可以是：

| 配置 | Recall@3 | 失败问题 | 观察 |
|---|---:|---|---|
| size=100 | 2/3 | Q2 | 正确来源被切断 |
| size=200 | 3/3 | 无 | Q2 召回，但候选更长 |

数据只说明这批问题上的结果，不代表所有情况，也不保证上线效果。

## 4. 一步一步手算一组结果

假设 gold set 有 3 个可回答问题，各自标注 1 个正确来源：`Q1→A`、`Q2→B`、`Q3→C`。某配置的 Top-3 候选如下：

| 问题 | Top-3 | 是否命中 |
|---|---|---|
| Q1 | A、D、E | 是 |
| Q2 | X、B、Y | 是 |
| Q3 | M、N、O | 否 |

命中的正确来源数是 2，总共标注了 3 个正确来源，所以整体 Recall@3 为 `2/3≈0.67`。候选总数是 9，但不能把 9 当分母，因为分母是标注的相关来源数，不是系统返回的所有文字。Q3 是漏召回；即使模型把答案写得很流畅，也不能因此说检索成功。

如果某题有多个相关来源，应先决定评估单位。例如 Q1 的标准来源为 A、B，Top-3 找到 A，则该题命中 1/2。多题可汇总相关来源后计算，也可逐题计算比例再求平均；两种都可用，但要说明选择。无答案题应单独记录系统是否错误地给出肯定回答，而不应硬塞一个“正确来源”。

## 5. 看排名与答案，不只看一个分数

两个系统可能 Recall 相同，但相关内容的排名不同。相关来源排第一，通常比排在 Top-k 之外更容易进入模型上下文。可以记录第一条相关结果的排名来补充分析；手工查看几题就足以理解，无需先安装评测框架。

实验的记录顺序可以是：固定语料和问题 → 记录设置（分块、模型、Top-k）→ 保存候选 ID → 按标准标注命中 → 抽查漏召回和噪声 → 再决定下一次唯一改动。这样当结果变差时，能回看是参数变化还是测试材料变化造成的。

还可以保存一次运行的“问题—候选—标注”原始表，而非只写最终的 `0.67`。例如 Top-3 中的 `A、D、E` 对 Q1，日后才发现 A 版本已经过期，就可以修正标注并重新计算；只保存总分便不知道哪些题受影响。课堂数据可用 Markdown 表格或 JSON 保存，字段保持一致即可。

比较分块策略时，除了命中与否，还要观察块是否保留完整上下文。一个大块可能找回答案但同时带入多个主题；一个小块可能精确，却缺少定义中的适用条件。把观察写在备注列，不必马上发明新指标。调参是为了解决可描述的失败，而不是为了让参数越来越复杂。

## 6. 多来源与不可回答题的标注

真实问题不一定只有一个标准来源。例如“退货要几天、商品要保持什么状态？”可能分别由退款期限页和商品条件页支持。标注时把两个来源都写出；Recall@k 的分母要计入两个相关来源。若只标其中一份，系统找回另一份也会被错误记为未命中，指标就不能反映实际检索能力。

不可回答题也要保留在集合里，但不要把它混进有来源问题的 Recall 分母。对这类题单独检查系统是否拒答、是否误引无关文本。之后如果资料增加了相关内容，就更新数据集版本并把题目标为可回答，避免同一题在不同运行中悄悄改变含义。

## 7. 把实验记录写完整

一条可复查记录至少有运行日期、语料/索引版本、问题集版本、切分和 Top-k 设置、候选 ID、命中判断及错误分类。举例：`Q3 / 正确来源 C / Top-3=M,N,O / 漏召回 / 下一轮只增加 chunk size`。这比写“调大切块后好像更准”更具体，别人也能重新算指标。

若候选变化但指标没变，仍值得查看排名和上下文：有时两个配置都命中同一来源，但其排名或附带噪声不同。练习结论应限定为“在这组样例上观察到……”，不能推广成任何文档都适用的规律。

## 8. 给失败案例贴上可操作标签

对每个失败题，建议写一个主要标签：`miss`（正确来源没召回）、`noise`（无关内容占据候选）、`boundary`（事实被切块边界拆开）、`answer`（证据已在上下文但回答错误）、`citation`（回答内容尚可但引用不对）。标签不是绝对真理，目的是让你下一步知道先看哪里。若一题同时有多个问题，可记录主因和次因，而不是强行只选一个。

例如正确资料完全没进入 Top-3，应记为 `miss`，下一步检查切块和召回；如果资料在 Top-3、但生成时模型引用了另一篇，应记为 `citation`，检查来源映射和答案核对。不要对两种错误都用“再加 Prompt”作为通用修复。

做完每轮实验后写一句范围有限的结论：“在 5 条课堂问题中，size=200 找回了 Q3 的来源，但带入更多无关文字；需扩大样本并检查答案忠实度。”这种结论诚实说明证据与未知，也自然引出下一步。

## 常见初学错误

- 对比两组时同时更改 chunk size、Top-k 和模型，无法判断原因。
- 只报告成功的一条样例，忽略失败和不可回答问题。
- 不写 Recall 的分母、k 值或相关来源定义。
- 看到回答错就改 Prompt，却不先查正确来源是否进入候选。
- 把检索召回率当成回答正确率。

## 练习（由浅入深）

1. **热身：算一题 Recall@k。**某问题标注有 `A、B` 两个相关来源，Top-3 为 `C、A、D`。验收：Recall@3 = `1/2 = 0.5`。
2. **跟做：构造 gold set。**写 5 个问题，其中至少 1 个在资料中无答案，为其标注来源和预期要点。验收：每个可回答问题有来源；不可回答问题标为“无”。
3. **独立完成：对比两种切分。**用同一问题集和检索方式，比较两种 chunk size，手算整体 Recall@3。验收：表格列出配置、分母、命中的相关来源、失败案例；指出一个漏召回、一个噪声召回，并选定下一轮唯一要改的因素。

## 今日验收与复习

- 同一问题集用于两组设置，Recall 的定义和分母明确。
- 先看候选再诊断回答，能分辨漏召回、噪声与生成误读。
- 结论针对测试集，不把小样本结论夸大成普遍规律。

**复习卡片：**如果正确文档没有进入 Top-k，单改生成 Prompt 能修复吗？为什么？

**小词典：**Gold set＝带人工参考标注的固定评测问题；Recall@k＝正确来源进入前 k 个结果的比例；噪声召回＝检索到但对问题无帮助的内容；回归测试＝改动后重新跑旧测试以发现退步。

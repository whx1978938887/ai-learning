# Day 7：客户端整合、GitHub 与 README

**今天的目标：**完成第一周成果整理，让他人可以安全、离线地复现 CLI 原型。

## 知识点

整合前拆清配置、模型适配器、流解析、历史和 CLI 的职责。README 要说明安装依赖、配置环境变量、运行方式、测试命令和已知限制。`.env` 应被 Git 忽略；删除已提交的密钥不等于撤销泄漏。测试语料与截图不得包含私人内容。

## 把前一周知识连成一个可以展示的成果

到 Day 7，不需要造出成熟产品；目标是做一个别人能运行、能理解、能测试的小程序。将它想成一间小餐馆：CLI 是服务员，历史管理是订单本，模型适配器是厨房接口，流解析器把逐步做出的菜安全地端出来，配置模块负责保管钥匙。各部分职责清楚，某一处故障才更容易定位。

```text
读取配置 ──> CLI 接收问题 ──> 会话历史
                              ↓
                   请求/Prompt 构造
                              ↓
                   模型适配器（Mock 或 API）
                              ↓
                流解析 + 错误/完成状态检查
                              ↓
                CLI 展示回答并更新历史
```

若先写一个最小程序，可以从固定流程做起：输入一行文本 → 交给 FakeModel → 打印其固定回答。确认数据流正确后，再逐步加入退出命令、历史、错误处理、流式解析。不要一口气把全部组件写在一个函数里。

### README 是给陌生使用者的操作说明

别人下载仓库后通常想知道：项目能做什么、需要什么环境、怎样安装、怎样配置、怎样启动、怎样测试、哪些功能还没有实现。README 的命令应与实际文件和依赖一致；如果只有 Mock 演示，就要诚实说明，不要声称已经连上某个真实服务。

### GitHub 发布前的安全清单

- 检查 `.env`、Key、访问令牌、私人聊天记录和个人文件是否被追踪。
- 只放虚构/合成示例数据；截图里也可能暴露秘密。
- 若密钥已推送到远端，先在服务商处撤销/轮换，不能仅靠新的提交删除明文。
- README 中只写环境变量名称和占位说明，不要写真正的值。
- 从一个干净目录按 README 重做一次安装与测试，证明说明可复现。

## 分层练习（由易到难）

1. **热身：**为项目写一句“它解决什么问题”和一句“当前不支持什么”。自测：读者不会误以为这是已上线服务。
2. **跟做：**用 FakeModel 串起 CLI 输入到固定回答，再加 `quit`、空输入和异常提示。自测：全程不需要 Key；每种情况行为清晰。
3. **独立挑战：**按上方图把已有模块接起来，执行所有离线测试。自测：成功、401、超时、流中断都能被区分；错误不显示 Key；主备切换只发生在明确允许的错误上。
4. **发布演练：**请自己假装是刚下载仓库的人，严格照 README 在干净目录操作。自测：依赖、配置、启动、测试命令都可执行；Git 状态里没有秘密或私人语料。
5. **小结：**用 3 分钟讲清输入如何变成回答，并指出一个失败边界。自测：不看代码也能说明各模块职责。

常见错误：README 复制旧命令；把 `.env.example` 当作真实密钥；只检查当前目录而忽略 Git 已追踪的历史文件；为演示方便而上传真实聊天数据。

### 先用 FakeModel 搭出程序骨架

在连真实服务之前，可以用固定行为的模型替身确认 CLI 流程。这样遇到问题时，能先判断是“界面/历史代码有问题”，还是“网络/服务商配置有问题”。以下示例可在 Python 中运行；它不会发送 HTTP 请求，也不需要安装 SDK：

```python
class FakeModel:
    def reply(self, messages: list[dict[str, str]]) -> str:
        question = messages[-1]["content"]
        return f"收到你的问题：{question}"


def answer_once(question: str, history: list[dict[str, str]], model: FakeModel) -> str:
    history.append({"role": "user", "content": question})
    answer = model.reply(history)
    history.append({"role": "assistant", "content": answer})
    return answer


history: list[dict[str, str]] = []
model = FakeModel()
print(answer_once("什么是 API？", history, model))
print(history)
```

先看数据变化：调用前历史为空；函数追加一条 `user`；模型用最后一条消息生成回答；函数再追加一条 `assistant`。重复调用时历史列表会逐渐增长。真实模型客户端应遵守类似的输入/输出约定，但要另行处理超时、HTTP 状态码、结构化结果和流式结束；Mock 的成功不能证明网络调用成功。

### README 可直接按这个顺序写

```text
# 项目名：一句话说明它做什么
## 功能：目前能做什么、明确不支持什么
## 环境：Python 版本/依赖/如何安装
## 配置：要设置的环境变量“名称”（不填真实值）
## 使用：从仓库根目录运行的命令
## 测试：离线测试命令以及预期结果
## 目录：重要模块各自的职责
## 限制与安全：Mock 范围、隐私和已知失败场景
```

每条命令都要在新终端实际试一次。命令中的路径、文件名、依赖名必须和仓库一致；若只能在特定目录运行，应写清先 `cd` 到哪里。没有验证过的命令不要写成“保证可用”。README 是使用者的第一份接口契约，不只是项目宣传。

安全检查时先区分“文件在磁盘上”和“文件被 Git 追踪”。`.gitignore` 只能阻止尚未追踪的新文件；已追踪文件仍可能被提交。可以检查工作区状态和忽略规则，但不要把 Key 粘贴到终端命令、截图或聊天内容中。若确认 Key 已公开，第一步是在服务商处撤销/轮换，再排查它是否还留在历史或日志中。

## 综合自测清单

- **输入路径：**空白输入不调用模型；输入 `quit` 后退出；普通问题只被追加一次。
- **历史路径：**同一会话的后续请求带必要上下文；新会话从空历史开始；失败的半截响应不作为完整 assistant 回答写入。
- **错误路径：**401 提示检查配置且不重试；可重试错误次数有上限；错误显示中不包含认证 Header。
- **发布路径：**不需要 Key 就能执行 README 的离线测试；干净目录能依说明启动；真实秘密和私人语料不在 Git 变更里。

## 动手练习

1. 将前几天的 Mock、历史管理、流式解析和错误处理接入一个 CLI。
2. 写 README：项目用途、安装、配置、启动、测试、限制。
3. 从干净目录按 README 执行；检查 `git status` 和仓库内容，确认没有密钥或真实对话。
4. 完成一次离线综合回归：参数校验器拒绝越界 `temperature`、`top_p` 和非正 `max_tokens`；SSE 跨块仍能拼出中文；主模型连续 503 后备用模型成功；401 不重试也不切换备用模型。
5. 对模拟结果统计质量、格式合规率、TTFT、总耗时和平均成本；少于 3 次的模型/题型标记样本不足，不给出可靠性结论。
6. 可选挑战：为重试器注入 fake sleep/random；实现 `Retry-After` 秒数边界处理；用 fake clock 测试熔断器 `CLOSED/OPEN/HALF_OPEN` 状态。

## 今日验收

- 无 API Key 时仍能运行离线测试。
- README 中每条命令可复现，错误提示不暴露秘密。
- 成功、401、超时和流中断都有自动化测试或明确测试步骤。
- 主备切换只对允许的错误生效；结果记录最终模型、重试次数、完成原因和可用的耗时/usage 指标。

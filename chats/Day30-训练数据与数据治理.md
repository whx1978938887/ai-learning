# Day 30：训练数据与数据治理

**今天的目标：**做一份小而可追踪的数据集，能说明每条数据从哪来、可用于什么，以及如何防止评估泄漏。

## 数据为什么需要治理

模型训练的样本会影响它学到的行为。错答案、重复答案、偏见或未经许可的数据，不会因为格式整齐就变可靠。**数据治理**就是为数据定规则：来源、授权、质量、访问、版本、保留期限和删除流程。

可以用 JSON Lines（JSONL）保存样本：每一行都是一份独立 JSON 对象。下面是纯虚构的示例，不含真实个人信息：

```json
{"id":"ex-001","source_id":"synthetic-v1","allowed_use":"training","task":"分类","input":"“包裹什么时候到？”","output":"物流查询","split":"train"}
{"id":"ex-002","source_id":"synthetic-v1","allowed_use":"training","task":"分类","input":"“请查一下配送进度。”","output":"物流查询","split":"train"}
```

真实项目还可记录创建日期、标注者/生成方式、数据版本、隐私审查、许可证或同意依据。`source_id` 让你可以找到同一来源的全部样本；`allowed_use` 明确用途授权。字段含义要写在数据说明中，而不是靠团队成员猜。

## 质量与数据切分

**训练集**用于学习；**验证集**用于开发过程中比较方案；**测试集**用于最终、尽量一次性的独立评估。测试集一旦被反复看答案来调整模型，实际上就被“用来训练决策”，最终成绩会过于乐观。

随机拆分并不总可靠：同一文档的不同段落、同一用户的近似问法，可能一份进训练集、一份进测试集。模型只需记住近似答案，测试结果就不代表泛化能力。因此要先按来源、文档、主题或用户分组，再切分；检查完全重复和近似重复。

一个简化的虚构拆分方案：

```text
source-A 的问法 -> train
source-B 的问法 -> validation
source-C 的问法 -> test
```

20 条样本只能验证流程，不足以证明真实产品质量。小数据试验要如实说明样本量和限制。

## 删除和版本追踪

若来源数据撤回授权，先用 `source_id` 找出关联样本，重新生成剔除后的数据版本，再确认训练/验证/测试文件及备份中的副本如何处理。已训练的模型未必能简单“忘掉”单条样本；按风险和要求评估是否重新训练、限制模型使用或采取其他合规措施。记录数据集版本、代码版本、基座版本和实验参数，才能复现结果。

## 常见错误

- 仅凭“格式正确”判断样本合格；内容是否准确、有代表性、获准使用同样重要。
- 把公开可访问误认为允许拿来训练。
- 只删掉名字，却保留可组合识别个人的细节。
- 同一来源的相似样本跨训练/测试集，造成数据泄漏。
- 训练期间反复查看测试答案、据此调参，最后仍把它称作“独立测试”。
- 没有来源记录，后来无法响应删除要求。

## 深入理解：数据行为什么要能追溯

数据治理不是给每条 JSON 加很多无用字段，而是为了能回答具体问题：这个样本是谁/什么流程产生的？授权允许拿来训练还是只能用于测试？标签由谁按什么规则确定？如果来源要求撤回，哪些文件和实验会受影响？一个简易数据字典就能说明字段，例如 `task` 是任务类别，`split` 是数据用途，`source_id` 标识一批共同来源。若人工标注，应保留标注规则版本；两个标注者不一致时，要记录裁决方法，而不是随意选一个答案。

可用 Python 标准库检查 JSONL 是否能解析并包含必需字段：

```python
import json

required = {"id", "source_id", "allowed_use", "input", "output", "split"}
with open("examples.jsonl", encoding="utf-8") as f:
    for line_number, line in enumerate(f, start=1):
        row = json.loads(line)
        missing = required - row.keys()
        assert not missing, f"第 {line_number} 行缺少字段：{missing}"
        assert row["allowed_use"] == "training"
```

这是格式示范，不代表样本内容真实正确，也没有检查隐私、重复或许可证。检查中发现问题要隔离该行并记录原因，不要悄悄改标签后保留旧版本。

## 切分数据要先分组再拆分

假设同一篇手册衍生了 12 个问答。如果按行随机分配，某些问答在训练集、换几个词的同源问答在测试集，模型可能只是记住了那篇手册。先以 `source_id`/文档 ID 为分组单位，把整组分到同一个集合，再统计每个集合的主题覆盖。类似地，来自同一会话或同一用户的高度相似样本通常不应跨集合。

“近似重复”没有唯一阈值：完全重复可通过规范化文本后比较；近似重复可先用简单相似度工具找候选，再人工抽查。规范化只用于发现重复，不应随意删除有意义的差异，例如否定词或不同金额。测试集要保存访问记录；如分析测试失败后要调整方案，应把这轮测试视为开发反馈，另准备未触碰的测试集再做最终评估。

## 来源撤回时的处置示例

若 `source_id=source-A` 撤回授权，先暂停这批数据继续使用；查询主数据表找出所有关联样本，重建 train/validation/test 文件及其校验和；检查派生标注、缓存、备份和训练产物目录；记录移除前后的样本量与版本。若已有模型使用过这批样本，评估是否需要重新训练或限制使用，不能轻率宣称删除样本就自动从模型中消失。处理完成后重新运行数据检查和相应评估。

## 质量抽查清单

抽样核对输入与标签是否一致；确认输出不含未经许可的个人资料；查看类别数量是否严重失衡；检查空文本、截断、编码异常和模板噪声；比较各数据集合的主题分布。类别不平衡并非一定错误，但报告结果时要说明，并同时报告每类指标，免得大类掩盖小类表现。

## 动手练习

1. **热身：**为一条虚构样本设计 `id/source_id/allowed_use/input/output/split` 字段。验收：另一个人能说出数据用途和来源。
2. **引导：**设计 20 条虚构指令样本及质量检查表。验收：检查空字段、错标签、重复、敏感信息和许可状态；没有真实用户数据。
3. **独立：**按来源或主题把样本分成 train/validation/test，并模拟撤回一个来源。验收：相似样本不跨集合；测试集没有用于训练/调参；能说明要重建哪些文件、记录哪些版本。

## 复习与词汇

- **复习：**相似问题分别进入训练和测试，会让测试成绩虚高，无法说明模型面对新问题的能力。
- **数据泄漏：**评估数据或其近似副本进入训练/调参过程；**数据集版本：**一组样本及其来源/规则的可识别快照。

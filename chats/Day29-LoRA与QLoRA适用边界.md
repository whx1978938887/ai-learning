# Day 29：何时微调、LoRA 与 QLoRA

**今天的目标：**先判断问题类型，再决定用 Prompt、RAG、工具调用还是微调；理解 LoRA/QLoRA 能省什么、不能省什么。

## 从“想改变什么”开始

大语言模型通常不会自动知道你最新的资料，也不会自动获得执行操作的权限。先把需求分成三类：

| 需求 | 通常先尝试 | 原因 |
|---|---|---|
| 指令更清楚、回答语气统一 | Prompt（提示词） | 改规则即可，成本低，容易撤销 |
| 引用公司手册、经常变化的价格 | RAG（检索增强生成） | 更新资料即可，不必重新训练 |
| 查订单、创建待办、发邮件 | 工具调用 | 需要访问外部实时系统或执行动作 |
| 稳定的风格、输出习惯或专门任务模式 | 评估微调 | 可能改变模型行为，但需高质量样本与验证 |

**微调**是在已有模型基础上继续训练，让其更适应一类任务；它不是把新事实安全地写进模型，也不保证正确。价格每周变化时，用训练记忆价格会迅速过时。处理订单也应使用有授权的业务工具，而不是让模型“猜”实时状态。

## LoRA 与 QLoRA

完整微调要更新模型的大量参数；LoRA（低秩适配）冻结大部分基座模型，只训练一小组可插拔的适配器参数，以减少可训练参数和存储。**基座模型**是原模型；**适配器**是学习到的增量。QLoRA 先以较低精度量化（用更少位数表示参数）基座，再训练 LoRA 适配器，以降低显存需求。

它们降低资源门槛，却不能消除显存、训练时间、数据清理、评估、版本管理、许可证和部署成本。具体能否运行依赖模型大小、量化方式、上下文长度和硬件；不要把“QLoRA”理解成“普通电脑一定能训练”。

## 一个决策示例

客服要求“语气友好，说明退货条件；退货政策可能变化；需要查询订单并发起退款”：

1. 用 Prompt 规定友好、简洁、先说明依据的语气。
2. 将最新退货政策放入可更新知识库，通过 RAG 检索并引用。
3. 订单状态由只读查询工具获取；退款工具要有权限检查与人工确认。
4. 只有当大量例子证明模型长期无法稳定遵循某种表达/分类规范，且 Prompt、工具和流程改进仍不够时，才评估微调。

## 评估与授权检查

微调前建立基线：固定测试问题、目标输出、正确性/格式指标、成本和延迟。再检查基座许可证是否允许用途，数据是否获准用于训练、是否含个人信息、是否能删除来源样本。不要因为实验小就忽略授权。

## 常见错误

- 混淆“让模型更会按格式回答”与“让模型知道实时事实”；前者可能适合行为微调，后者通常需要外部数据。
- 动态事实交给微调记忆，后来事实变更却没有可靠更新办法。
- 认为 LoRA 只需很少数据就必然有效；样本质量和覆盖面仍关键。
- 把训练 loss 下降误认为业务效果提升。
- 忽略基座和数据许可证，或把未授权用户对话放入训练集。
- 为“用上微调”而微调，未先做 Prompt/RAG/工具的对照。

## 深入理解：选择技术时看知识变化在哪里

想像客服需要回答“退货期是几天”。若答案写在一份经常更新的政策文件中，RAG 可在每次问题到来时检索当前版本，并把原文引用给用户。政策更新只需更新资料库并重新索引相关文档，不需要重新训练模型。若问题是“用户这句话属于投诉还是咨询”，类别定义稳定、例子充足，微调可能改善分类行为，但必须用没参与训练的投诉样本验证。若问题是“请查我的订单现在在哪”，模型本身既不知道实时订单，也无权访问账户；应由已授权的只读工具查询，再将结果交给模型组织语言。

Prompt 是明确告诉模型当前任务的指令，适合低成本试验，但上下文变长或要求太多时可能不稳定。RAG 提供可替换的外部证据，适合频繁更新且需要来源的知识。工具调用解决“读取/改变外部状态”，需要应用侧鉴权。微调更像改变模型的默认技能或表达倾向，不能取代资料库和权限系统。一个产品也可能组合多种方法，而不是四选一。

## LoRA/QLoRA 的成本不是只有显存

LoRA 的“低秩”可直观理解为用一组较小的矩阵变化去近似对大模型权重的调整；训练时保留基座，大部分参数不更新，产物常是一个相对小的适配器文件。推理时仍需加载兼容的基座和适配器。换基座版本后，适配器未必兼容，因此必须记录精确模型版本。

QLoRA 将基座权重用较低精度表示以节省显存，训练仍要保存适配器及部分优化状态。真实资源还取决于序列长度、batch、优化器、显卡显存和软件版本。训练成本之外，还要计入清理/授权数据的时间、基准集标注、失败实验、评估推理、模型部署、适配器版本和监控。若一条简单 Prompt 就能达到门槛，训练可能是更贵且更难维护的方案。

## 一个可比较的微调实验

先准备三组互不混用的数据：训练样本用于学习，验证样本用于选超参数，测试样本只在候选方案锁定后使用。建立“当前 Prompt + 基座”的基线，再训练 LoRA 候选。对两者运行同一组测试，逐题标注正确、格式、安全、依据是否充分，同时记延迟和资源消耗。预先写门槛，例如“目标类别不得低于 90%，安全用例全部通过，单次成本不超过预算”；小样本的比例要同时报告分母，避免把 9/10 写成笼统的“90%可靠”。

## 数据和许可证检查的具体问题

要确认基座许可证是否允许商业/研究/再分发用途，是否有使用限制；训练数据是否允许机器学习用途、是否包含可识别个人信息；样本能否按来源追踪和删除；产物是否可能复现训练文本。若答案不明确，暂停使用并寻求适当的许可/合规意见，而不是假设“互联网上能看到就能训练”。

## 动手练习

1. **热身：**为“每周更新的价格、统一客服语气、实时查订单”各选一种起始方案。验收：分别选 RAG、Prompt、工具调用并说明原因。
2. **引导：**分析上述客服案例，列出每种技术的输入、更新方式、失败风险。验收：退款不能由模型文本直接执行；价格变更不依赖重新训练。
3. **独立：**挑一个稳定任务提出是否值得微调的实验计划。验收：有基线、固定测试集、许可证/数据审查、质量和成本门槛，并给出“不微调”的判定条件。

## 复习与词汇

- **复习：**动态价格用微调保存为何易过时？训练所得行为不等于可查询、可及时更新的数据源。
- **量化：**用较少位数存储数值；**基座：**作为起点的原模型；**LoRA 适配器：**与基座搭配的小型可训练参数。

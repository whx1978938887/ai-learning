# AI 应用开发学习计划：45 天每日讲义索引

本文是看板 **45 天每日讲义索引**。每天一份 Markdown，包含当天知识点、练习和验收标准；按看板当天任务推进，不需要先读完整个阶段。全路线先修 Python 函数/列表/字典/异常、HTTP/JSON、终端、虚拟环境和 Git；练习优先用 Mock 和本地样例，没有 API Key、GPU 或云主机也能完成。前 5 周是技术学习，第 6 阶段 10 天用于职业准备，总计 45 天。

## 如果你是编程小白，先这样学

这套资料会同时出现 Python、HTTP、向量检索、Agent 等新词。第一次看不懂很正常，不要背名词，先追问三个问题：**它要解决什么麻烦？输入是什么、输出是什么？没有它时会发生什么？** 每份讲义按“生活化直觉 → 术语解释 → 小例子 → 动手练习 → 自测”的顺序读；遇到代码，先读注释和输入/输出，不必一开始就记住每个标点。

每天先完成约 30 分钟的核心学习；想做完全部练习和扩展案例时，可安排 45–60 分钟。先用 3–5 分钟复述昨天内容；花 10–15 分钟读今天的一个小节，每读完就合上页面讲一遍；花 10–25 分钟做练习；最后用 2–5 分钟记录不会的词和错误。**练习比读完更重要**：读懂示例不等于会做，至少亲手改一次输入并观察输出。卡住超过 10 分钟时，把问题缩小到一个词、一个输入或一行报错，再继续。

### 代码练习的约定

- `输入`是程序收到的资料，`输出`是程序交回的结果；先确认两者，再读中间步骤。
- 示例若写“伪代码”，是解释流程而不是可直接运行的 Python；写了完整 Python 的代码块才按 Python 示例理解。
- `...`、`你的代码`、`TODO` 是待补内容，不是 Python 语法。引用模型服务商的字段/API 时，以你实际使用的版本文档为准。
- 优先用虚构数据、Mock（假对象）和本地文件练习。没有真实 API Key 也能学设计、错误处理、检索和测试。
- 不认识错误信息时，先读最后一行，再看报错指出的文件/行号；不要把 Key、个人资料或私有文件内容贴到公开渠道。

每份每日讲义的练习由易到难：先确认术语与结果，再照步骤完成一个小例子，最后独立处理一个新情况。若当天练习未通过，只回看对应小节并重做错题；无需从头重读，也不要靠复制代码冒充掌握。

## 学习约定

- LangChain、LlamaIndex、模型 API 与评估工具会迭代：锁定项目版本，查对应版本文档，不把旧接口当作唯一用法。
- RAG 的改进要先有固定评估基线；Agent 工具必须校验参数、限制权限、设置超时与循环上限，高影响操作需确认。
- API Key 不提交 Git；网页、文件与检索片段是不可信输入；日志避免记录密钥和无必要的个人信息。
- 每天以“闭卷复述 + 完成练习 + 说明一个失败边界”作为完成标准；没达到时重练薄弱点，不以阅读时长代替掌握。

## 学习规则：短输入，马上输出

核心学习约 30 分钟；完成全部阶梯练习约 45–60 分钟：

1. **目标预览（2 分钟）**：读本节目标，想想自己已经知道什么。
2. **带问题阅读（10 分钟）**：只读本节对应部分；读完一个知识点就合上笔记，用自己的话说出来。
3. **闭卷练习（12 分钟）**：先独立完成练习，再查看参考结构或检查清单。API 练习优先离线，不需要真实密钥。
4. **纠错与记录（4 分钟）**：只记下“错在哪里、下次怎么检查”，不要抄整篇笔记。
5. **口头复述（2 分钟）**：不看材料，讲清楚本节解决的问题和一个易错点。

当天时间不足时，至少完成“目标预览 + 一个练习 + 口头复述”，不要把只阅读算作完成。

## 复习节奏：让知识留得住

每次学习后的复习都先闭卷回忆，再查笔记；复习不需要重读整篇。

| 时间 | 用时 | 做什么 |
| --- | --- | --- |
| 当天结束 | 2 分钟 | 写下 3 个关键点和 1 个仍不确定的问题 |
| 次日 | 5 分钟 | 不看笔记复述；重新做错题或微练习 |
| 第 3 天 | 5 分钟 | 做一题混合练习，说明选择依据 |
| 第 7 天 | 10 分钟 | 完成一个小应用，并用验收清单自评 |

答错时不要马上重读整篇：先定位到对应小节，读完后合上材料，重新做同一道题并解释修正原因。

## 完成标准

每节分别为以下三个维度按 0–2 分自评，总分 6 分：

- **知识回忆**：0 分表示看了材料仍不能复述；1 分表示需要提示；2 分表示不看材料能讲清关键概念。
- **动手练习**：0 分表示未完成；1 分表示需要提示或未覆盖边界；2 分表示独立完成核心验收项。
- **错误解释**：0 分表示无法定位错误；1 分表示能指出问题但说不清原因；2 分表示能解释失败场景和检查方法。

达到 **至少 5/6 分**，且本节核心练习通过，才进入下一天；未通过只重练失分知识点。Day 7 的作品还应能离线复现、说明输入输出，并包含至少一个失败用例。

## 练习约定

- 编程题默认使用固定数据、Mock 或假时钟，不让网络、真实费用和等待时间成为学习障碍。
- 每题先写预期结果或测试，再写实现；遇到错误先说明原因，再看提示或参考答案。
- Prompt 实验固定输入和评分标准；一次只改变一个变量，否则无法判断哪项修改带来提升。
- 不把“模型听起来更流畅”当作效果提升；检查正确性、格式、边界处理和重复测试的一致性。
